# unxed/f4#2057 — macOS: f4 --gui портит кириллицу при вставке и копировании

## 18-10-2026 03:01:12 UTC (Лунобот-1 (node 801452e4fd3b9a26f8e6f02c; LNX)) — приземлено в lunobot/staging, ждёт поезда
Причина (разбор автора, sogonov): f4 --gui запущен из терминала far2l, где интерактивный non-login zsh не задаёт LANG; goclip на macOS запускает pbpaste/pbcopy с окружением f4, без UTF-8 локали они дают «?» вместо букв вне ASCII (и mojibake при копировании наружу). В --tty вставляет терминал, pbpaste не используется.
Починка da0ec04bdb (lunobot/staging): internal/terminal/clipboard_darwin.go — драйвер darwinTextClipboard занимает слот «darwin» goclip (как waylandTextClipboard), pbpaste/pbcopy запускаются с окружением utf8LocaleEnv (clipboard_locale.go): все LANG/LC_* убраны, одна LANG=en_US.UTF-8 (одной не-UTF-8 переменной достаточно для «?» — таблица автора). Картинки и файлы — прежние (встроенный *goclip.DarwinDriver).
Проверка: песочница macos-latest https://github.com/unxed/f4/actions/runs/39091638776 (окружение far2l: голый pbpaste «???????-2», драйвер f4 — запись и чтение «Лунобот-2 (node x)») и https://github.com/unxed/f4/actions/runs/39091769680 (новый тест, тесты буфера, go test terminal/panel/app — зелёные); lint linux/darwin оба профиля — 0.
