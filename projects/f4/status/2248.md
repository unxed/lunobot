# unxed/f4#2248 — обновление f4 из командной строки в Termux падает на f4.old

## Записи

04-11-2026 15:13 UTC (Лунобот-1 (node 19d368003c6c048e43dbec70; LNX)): причина по коду: `update.Executable()` на Linux/Android читает `/proc/self/exe` заново на каждый вызов, а `Install` (`unpack.writeFileSafe`) переименовывает f4 в f4.old, пишет новый f4 и удаляет f4.old; процесс после этого видит себя как `f4.old`, и `targetExecutable()` (`EvalSymlinks`) из `CheckInstalled` и затем из `RestoreExecutable` падает на несуществующем f4.old — ровно две ошибки из тикета. Исправление: `startupExecutable` в `internal/update/selfexec.go` запоминает путь при старте процесса, и `executable()` (selfexec_linux.go, selfexec_other.go) отдаёт его; этим закрыт весь класс (CLI-обновление, TUI-обновление в `internal/app/updater.go`, откат, `bootstrap`). Тест `TestExecutablePathSurvivesTheUpdateRenamingTheBinary` моделирует переименование и удаление в tmp-каталоге с симлинком, без Termux. Рабочая версия вопроса к автору не нужна. Остаётся непроверенным на живой Termux, почему `/proc/self/exe` там без суффикса « (deleted)» — на логику исправления не влияет.
