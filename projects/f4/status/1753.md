# f4#1753 — ZIP: exe/dll/db пишутся без сжатия

Причина (16-10-2026): `analyzeBlock` в unxed/zip (`archiver.go`) помечал блок «store», если в первых 64 КБ больше 224 различных байтов; у любого бинарника их 256. Образцы автора: dll — энтропия 6,2, deflate 0,51; db — 7,8 и 0,81.

Сделано: PR unxed/zip#21 (ветка `lunobot/pr/zip-store-heuristic-1753`, коммит `5689b60`) — решение по энтропии (порог 7,9 бит/байт) + два теста. Строка в `projects/zip/CI.md`.

Осталось:
1. Довести unxed/zip#21 по § 5 п. 3 (зелёный — влить, красный — чинить в той же ветке; покрытие zip 100%).
2. Тег релиза zip (по паспорту/практике репозитория), затем bump `github.com/unxed/zip` в `go.mod` f4 (и, если zipper закрепляет старую версию, проверить MVS): `land` с `Touch: #1753`, трейлер `Sandbox-Full:` (правка go.mod, § 7.2 п. 0), секции `Проверить:`/`Проблема:`/`Исправление:`.
3. «Пробуйте!» автору: Shift+F1 на dll/db — внутри ZIP метод Deflate.
