Сделано: `internal/terminal/far2l_dnd_client.go` — `DNDClient`: `Bind` сам выбирает binding (crypto/rand, как
offer-id терминала) и шлёт BIND, `Unbind` выключает; `List`/`ListAll` (постраничный dispatcher по `next_cursor`,
без ручной работы с курсором у вызывающего) и `Read` шлют DND/LIST и DND/READ; `Close` идемпотентен, при
исчерпании RID-таблицы падает на RID=0 best-effort (§ 8 п.2 спецификации). `HandleFrame` — единая точка входа
входящих reply/event кадров: `FrameReply` резолвит ожидающий вызов по RID, `FrameEvent` зовёт `OnEvent` только
для `INPUT_DND` своего текущего binding; чужой RID, чужой код события и `FrameRequest` (обратное направление)
безопасно игнорируются/отвергаются — расчёт на то, что `HandleFrame` в будущем сможет сидеть на канале, общем
с другим far2l-трафиком. Главное правило файла (§ 8 спецификации): отмена `ctx` вызывающего НЕ освобождает его
RID — `roundTrip` при `ctx.Done()` просто возвращает ошибку, не трогая таблицу ожидания; освобождает RID только
`deliver`, когда настоящий ответ действительно пришёл и разобран. `window` в этом шаге всегда 1 (единственный
профиль, который отдаёт `dndServer`); неблокирующий dispatcher для `window>1` — в шаге 4, как и было
запланировано. Кодек `far2ldnd` переиспользован без изменений с обеих сторон. Тесты (`far2l_dnd_client_test.go`)
— клиент против `dndServer` из шага 2 напрямую в процессе, без реального терминала: полный цикл
BIND→INPUT_DND→ListAll→Read→Close по настоящему wire-формату; отмена запроса в середине полёта — RID остаётся
занят, поздний ответ приходит и освобождает его, затем настоящий CLOSE; fallback на RID=0 при исчерпании
таблицы — изолированно, без сервера; `HandleFrame` игнорирует чужой RID/чужое событие и отвергает
`FrameRequest`; определение старого сервера (пустой ответ после RID → `far2ldnd.ErrNoDND`) на BIND.
