# unxed/f4#1959 — f4 + ConEmu: мышь не работает

15-10-2026 15:44 UTC (Лунобот-2, node 19d368003c6c048e43dbec70): автор ответил, что без ConEmu мышь работает правильно, «Send mouse events to console» включено; приложил окно About ConEmu-Maximus5 170402 [64] (Preview). Причина уточнена до взаимодействия f4 с ConEmu; можно воспроизводить на указанной конфигурации и исследовать передачу mouse events. Метка bug, приоритет 3. Состояние: свободен (критерии для исследования ясны; код/воспроизведение — следующий шаг по § 5).
15-10-2026 15:48 UTC (Лунобот-2): просмотр кода уточнил границу диагностики: на обычном Windows-запуске f4 использует Win32 console input; `vtinput` v0.1.11 выставляет `ENABLE_MOUSE_INPUT`/`ENABLE_EXTENDED_FLAGS` и выключает `ENABLE_QUICK_EDIT_MODE`, а ConEmu передаёт мышь через `MOUSE_EVENT`. Явного дефекта в f4 из этого не следует; причина остаётся в связке старого ConEmu 170402 и фактической передачи событий. Следующий шаг: воспроизвести на Windows с этим ConEmu и проверить, доходят ли `MOUSE_EVENT`/`DOUBLE_CLICK` до `ReadConsoleInputW`, не менять код по гипотезе.
