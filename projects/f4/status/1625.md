- Шаг 1 (Лунобот-3, 28-09-2026, f4 `4e3a57a7` в `lunobot/staging`):
  F3 на `.md/.markdown/.mdown/.mkd` → `tryOpenMarkdownViewer` в
  `openViewerInternalMode` (`internal/app/markdown_view.go`), обёртка
  `markdownView` над `vtui.NewMarkdownView` (vtui v0.1.375, уже в go.mod):
  на всё рабочее пространство, не модальное, заголовок = имя файла,
  F3/F10/Esc — закрыть, F4 («Text») — закрыть и открыть обычный вьювер
  (`openPlainViewer`, вынесенная «простая» половина `openViewerInternalMode`).
  За настройкой `ViewerOpenAsSupportedType`; >4 MiB или ошибка чтения — в
  текстовый вьювер. Песочница: vet ./internal/... + test internal/app,
  internal/i18n — зелёные (run 36434822977).

- Шаг 2 (Лунобот-3, 28-09-2026, vtui `7674c9c4` в `lunobot/staging` vtui):
  `ParseMarkdownTopic` на `github.com/yuin/goldmark` v1.8.6 (CommonMark +
  таблицы, task lists, linkify; strikethrough НЕ включён — он съедает
  одиночные `~`, напр. `~/src`). Заголовки, **жирный**/*курсив*/`код`
  (все — выделением, в палитре help один цвет), ссылки/картинки/автоссылки/
  e-mail, абзац = строка (переносит HelpView), hard break, блоки кода
  буквально с отступом 4, списки (•, номера со start, вложенность),
  цитаты `│`, `---` → линия, таблицы с выравниванием колонок, HTML-блоки
  буквально, `<!-- -->` скрыты. В разметку help добавлен экран
  `helpLiteral` (`\x10`) для литеральных `#`/`~`/`^`; его понимают
  parseHelpCells/helpCellsMarkup, parseHelpLinksInto, renderLine,
  findLinkAt. Публичный API не менялся. Дамп всех 23 .hlf f4 (символы,
  цвета, зоны клика ссылок; ширины 76 и 30) до/после совпал байт в байт
  (sha f524a64d…). Песочница: vet + `go test .` зелёные (run 36436810062).

## Зависимость от vtui

До шага 2 компонент vtui (`markdown.go`, `ParseMarkdownTopic`) — свой regex-разбор:
только ATX-заголовки, `**bold**`, ссылки; курсив/списки/code fences/таблицы
идут как текст, `#`/`~`/`@` в тексте ломают разметку help-движка (в code
fences строка `# comment` становится заголовком).
