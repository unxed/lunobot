# unxed/f4#1722 — рамки на Windows 7

03-10-2026: захват разобран. Скриншот подтверждает не ошибку геометрии f4, а
неверное отображение всех Unicode box-drawing символов классической консолью
Windows 7: вертикальные/горизонтальные линии и углы превращаются в треугольники.

Причина находится в зависимости `unxed/vtui` v0.1.393: `symbols.go` всегда
выбирает Unicode box-drawing для Win32 console, а `WriteConsoleOutputW` на
legacy conhost Windows 7 не даёт надёжного glyph rendering. У vtui уже есть
аналогичный ASCII fallback для FreeBSD syscons.

Подготовлен и повторно проверен патч к `unxed/vtui` (не отправлялся в другой
репозиторий согласно правилу проекта). Полная копия патча лежит рядом в
[`1722-vtui.patch`](1722-vtui.patch):

```diff
diff --git a/symbols.go b/symbols.go
@@
-\tif IsFreeBSDConsole {
+\tif IsFreeBSDConsole || legacyConsoleBoxDrawing() {
diff --git a/legacy_console_box_stub.go b/legacy_console_box_stub.go
new file mode 100644
--- /dev/null
+++ b/legacy_console_box_stub.go
@@
+//go:build !windows
+
+package vtui
+
+func legacyConsoleBoxDrawing() bool { return false }
diff --git a/legacy_console_box_windows.go b/legacy_console_box_windows.go
new file mode 100644
--- /dev/null
+++ b/legacy_console_box_windows.go
@@
+//go:build windows
+
+package vtui
+
+func legacyConsoleBoxDrawing() bool {
+\treturn !isWineOS() && hasConsoleBufferOS() && !hasVTConsoleSupportOS()
+}
```

Патч не приземлялся в f4: он требует сначала принять изменение в `vtui`, затем
поднять зависимость f4 с v0.1.393 на новую версию. Проверка сборки на реальном
Windows 7 ещё не выполнена.
Следующий шаг: после применения патча собрать Windows-артефакт и проверить
рамки на том же Win7; до этого тикет остаётся открытым, а патч передан владельцу
через учётный репозиторий.
