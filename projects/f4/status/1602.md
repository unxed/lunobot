# f4#1602 — DOS Navigator/far2l directory tree panel

Тикет владельца: реализовать в f4 панель-дерево каталогов по образцу
far2l (`far2l/src/panels/treelist.cpp`/`.hpp`), обе модели — данные
(плоский список `TreeItem` с раскрытием/сворачиванием через
вставку/удаление диапазона строк, без честного nested-дерева) и UX
(временный оверлей поверх активной панели, вызываемый по хоткею; Enter
— навигатор; F5/F6/F7/F8/Del/Ctrl+R работают прямо по подсвеченному в
дереве узлу, без захода в него).

## Сделано (лендинг в `lunobot/staging`)

1. `34473c65` — первая атомарная часть: панель Дерево по Ctrl+T как
   AltPanel (та же модель, что у Info/Quick View). Плоский список
   `treeItem{name, path, depth, parentIndex, expandable, collapsed,
   last []bool}` по образцу far2l, ленивое раскрытие
   (`expandAt`/`collapseAt`/`spliceChildren`), корень — весь текущий
   том (не только текущий каталог), путь до текущего каталога активной
   панели уже развёрнут при открытии. Enter — перейти и закрыть;
   Right/Left — раскрыть/свернуть узел под курсором.
2. `6fde5fc3` — фикс CI (darwin/arm64, windows/amd64):
   `revealPath`/`resolvePath` не находили путь через символическую
   ссылку или короткое Windows-имя компонента пути; добавлен fallback
   на `os.Stat` (`revealChild`) и регистронезависимое сравнение на
   Windows.
3. `f005aaca` — F5/F6 (copy/move) с фокусом на дереве действуют на
   подсвеченный узел как цель, а список файлов берётся из соседней
   панели, открывшей дерево (`TreePanel.SelectedPath`,
   `treeCopyMoveTarget`).
4. `79004c4a` — F7 (mkdir) создаёт подкаталог внутри подсвеченного узла
   дерева, затем `RefreshChildrenAndSelect` пере-сканирует его и ставит
   курсор на новый подкаталог.
5. `ca47b15c` — F8/Del/Shift+Del удаляют подсвеченный узел дерева
   (тот же диалог подтверждения/trash-логика, что и у обычной панели);
   `RefreshAfterDelete` переставляет курсор на соседний узел; корневая
   строка дерева (весь том) отказывает в удалении
   (`IsRootSelected`, `fileDeleteEnabled`).
6. `241f6a8b` — Ctrl+R с фокусом на дереве пересканирует именно дерево
   (`TreePanel.Rescan`), а не `RefreshAll()` (который проходил только
   по обычным панелям и не трогал `AltPanels`): пере-читывает с диска
   все уже раскрытые каталоги, сохраняя курсор на прежнем/ближайшем
   существующем узле.
7. `ce4a6c5e` (этот шаг) — второй из двух follow-up'ов, названных в
   доккомменте первой части: булева настройка f4:config
   `Panel.TreeRootWholeVolume` (Settings Center: Panels > Directory
   tree), по умолчанию включена (сохраняет текущее поведение). Выключена
   — дерево (Ctrl+T) открывается с корнем на текущем каталоге исходной
   панели, а не на всём томе. `NewTreePanel` теперь считает корень через
   новый хелпер `treeRoot`; остальная механика (ленивое раскрытие,
   F5/F6/F7/F8/Del/Ctrl+R) не менялась — `resolvePath` уже возвращал
   саму корневую строку, когда целевой путь совпадает с корнем, отдельный
   случай не понадобился. Новый тест
   `TestNewTreePanel_RootAtCurrentDirWhenConfigured`.

**Проверено:** `gofmt -s -l` — пусто; `go run ./tools/langfmt` — без
изменений (новые тексты настройки резолвятся через
`f4settings.Text.English`-фоллбэк, отдельных `.lng`-ключей не
потребовалось). `go build`/`go vet`/`go test` не запускались локально
(правило флота) — результат `quick`-прогона смотри через `train.py
covered unxed/f4 ce4a6c5e` (или более поздний коммит, если поезд уже
увёз это дальше).

## Осталось (следующий шаг/шаги)

1. **Персистентный кеш раскрытия/сворачивания узлов между открытиями
   панели дерева** — единственный оставшийся follow-up, названный в
   доккомменте первой атомарной части (`34473c65`) и оставшийся в
   доккомменте `TreePanel` и сейчас: сейчас при каждом новом `Ctrl+T`
   дерево строится заново (раскрыт только путь до текущего каталога
   активной панели), состояние раскрытых узлов предыдущего открытия
   не сохраняется. Нужно решить: где живёт кеш (глобальная
   package-level карта path -> раскрыт/свёрнут, per-VFS-root или
   per-src-panel), когда инвалидируется, и стоит ли переживать сам
   процесс f4 (сохранение в settings.ini) или только in-memory на
   время сессии — владелец эту развилку явно не комментировал, стоит
   спросить перед реализацией, если неочевидно после чтения тикета
   ещё раз.
2. Собственно тикет исходно — открытый пункт "новые фичи и всё, что
   требует нескольких шагов" (приоритет 5); после п.1 выше можно будет
   переоценить, остался ли у тикета дальнейший открытый объём (даже
   бегло не похоже на TODO-список от владельца, кроме кеша раскрытия) —
   тикет не закрывать самостоятельно в любом случае (правило флота).
