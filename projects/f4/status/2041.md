В f4 нет COM-обвязки (go-ole не в зависимостях, только golang.org/x/sys/windows), IContextMenu/TrackPopupMenu нигде не используются. План (только windows, новый файл internal/app/explorer_menu_windows.go + заглушка для прочих ОС):
  1. CoInitializeEx(APARTMENTTHREADED) в отдельной горутине с runtime.LockOSThread; SHParseDisplayName(путь) → PIDL; SHBindToParent(PIDL, IID_IShellFolder) → папка + дочерний PIDL; IShellFolder::GetUIObjectOf(hwnd, 1, &child, IID_IContextMenu) → IContextMenu (вызовы через vtable syscall.SyscallN).
  2. Своё скрытое окно (WS_POPUP, класс f4ExplorerMenu) в этом же потоке: TrackPopupMenuEx требует окно потока-владельца, окно консоли принадлежит conhost. CreatePopupMenu + IContextMenu::QueryContextMenu(CMF_NORMAL|CMF_EXPLORE) → SetForegroundWindow(окно) → TrackPopupMenuEx(TPM_RETURNCMD|TPM_RIGHTBUTTON) в координатах курсора (GetCursorPos; в консоли — позиция строки курсора панели через GetWindowRect окна консоли, позже).
  3. Выбранный id → IContextMenu::InvokeCommand(CMINVOKECOMMANDINFOEX, lpVerb = MAKEINTRESOURCE(id-1)); подменю «Отправить», «Открыть с помощью» требуют IContextMenu2/3::HandleMenuMsg2 в оконной процедуре (WM_INITMENUPOPUP, WM_DRAWITEM, WM_MEASUREITEM, WM_MENUCHAR) — сделать во втором подшаге.
  4. Привязка: действие File.ExplorerMenu (меню «Файлы», Visible только windows); клавиша — по ответу автора (Apps уже занята «Системными свойствами»: варианты Shift+Apps или перенести свойства).
