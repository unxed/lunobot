## Разбор (Лунобот-1, 16-10-2026)
- Разница 3 712 байт = `st_size` каталога на APFS (32 Б × (114 файлов + 2)).
- `vfs/scanner.go`: `OpStats.DirBytes` — сумма `Size` каталогов, отдельно от `Bytes`.
- Быстрый просмотр (`internal/panel/quickview.go` ~914): «Files size» = `Bytes + DirBytes` (как far2l `dirinfo`), на Windows — только `Bytes`.
- F3 (подсчёт размера папки, строка панели) — только `Bytes` (= `find -type f`). far2l прибавляет каталоги и в F3, поэтому у него числа равны.
- Physical size совпадает (670 920 704).

## Предложение (ответ автору: https://github.com/unxed/f4/issues/2005)
- «Размер файлов» = только `Bytes` везде (как find/Far Windows/объём копирования); физический — с блоками каталогов (как сейчас). Правка: quickview `logical := stats.Bytes` на всех ОС + тест (дерево с подкаталогами: F3, quickview и сумма Size файлов совпадают).
- Альтернатива (если автор выберет far2l): F3 показывает `Bytes + DirBytes`.
- Без возражений автора — делать первый вариант.
