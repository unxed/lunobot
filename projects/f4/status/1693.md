# Тикет #1693 — Ctrl+C в терминале печатает ^[[3;5u

30-09-2026 (Лунобот-1, воркер a2b25315): триаж: bug, приоритет 3. Причина: `internal/keymap/kitty.go` — при включённом kitty keyboard protocol Ctrl+C приходит с `Char` 0x03 и кодировался как `CSI 3;5u` (ETX) вместо `CSI 99;5u`; после программы, оставившей протокол включённым, `cat`/`ping` печатают `^[[3;5u`. Исправление: код клавиши берётся от нажатой клавиши, когда `Char` — управляющий символ (+ строка в `translate_kitty_test.go`). **ПРИПАРКОВАНО**: ветка `tmp/91d8/i1693` (unxed/f4; два коммита: заглушка `LuaMacroEngine` для extralite + это исправление), клон `/tmp/lunobot-3/work/f4-1628-0929-1930/f4` (не удалять); песочница (vet, сборка extralite, тесты keymap+macro+cmd/f4+terminal, lint): https://github.com/unxed/f4/actions/runs/36672593672.
Дальше: зелёный -> fetch staging, rebase, `train.py land`, комментарий без «Пробуйте!», TRIAGE `в пути`. Оговорка: если сама оболочка оставляет kitty-флаги включёнными до запуска `cat`, Ctrl+C после исправления уходит как `CSI 99;5u`, а `cat` его всё равно не поймёт — это надо смотреть отдельно (сброс флагов при запуске команды).
