# unxed/f4#1998 — macOS: окно Sudo Elevation снова и снова при быстром просмотре (Ctrl+Q)

**Тикет:** https://github.com/unxed/f4/issues/1998 (sogonov, сборка 46dbbb9, f4 gui macOS)
**Приоритет:** 3. **Состояние:** `свободен`.

## Причина (триаж Лунобот-1, 16-10-2026)
Та же, что у f4#1993 (часть 2 в `status/1993.md`): подсчёт размера папки (здесь — быстрый просмотр) обходит вложенные каталоги (`vfs/scanner.go` `scanRecursive`, ошибки `ReadDir` глотаются), `OSVFS.ReadDir` для закрытого каталога идёт через `globalSudoClient.ReadDir`, каждый запрос askpass (`vfs/sudo_askpass_unix.go` `handleAskpassRequest`) показывает диалог пароля; отказ (пустой пароль/Esc) не запоминается.
Часть 1 f4#1993 (`sudoReadDirCancellable`, отмена контекста отпускает подсчёт) уже в main ee3113a7d — у автора сборка старше.

## План (ответ автору: https://github.com/unxed/f4/issues/1998#issuecomment-6218559914)
- «Липкий» отказ на одну операцию: значение в `context` операции (подсчёт размера для F3/Ctrl+Q, копирование, поиск) — после отказа от пароля последующие `ReadDir`/`Open` через sudo в этом контексте сразу возвращают ошибку доступа без запроса; новая операция спрашивает снова один раз. Согласие — дальше работаем с повышенными правами (как сейчас).
- Висящий диалог пароля закрывать при отмене контекста операции (askpass-запрос сейчас не знает об отмене).
- Единообразно во всех местах, где сканер/операция идут через `OSVFS` (не только быстрый просмотр).
- Тесты: сканер с подменённым sudo-клиентом — после отказа второй закрытый каталог не вызывает запрос; новая операция вызывает.
- Делать вместе с частью 2 f4#1993 (один коммит с `Touch: #1993` и `Touch: #1998`).
