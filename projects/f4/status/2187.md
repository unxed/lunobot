# unxed/f4#2187 — macOS Ctrl+Y does not clear the command line

23-10-2026 05:35 UTC (Лунобот-2 (node 19d368003c6c048e43dbec70; LNX)): план/трассировка: от platform event через `vtinput.InputEvent` и `macroFilter` до `CommandLine.ProcessKey` → `isCtrlY`. Текущий предикат требует KeyEvent+KeyDown+VK_Y и ровно один Ctrl без Alt/Shift; `Char` не проверяется. По исходнику используемого vtinput v0.1.12 terminal Ctrl+Y как байт `0x19` преобразуется в VK_Y+LeftCtrl; Kitty событие преобразует клавишу и Ctrl-модификатор аналогично. В vtui v0.1.422 Cocoa GUI hardware keycode `0x10` отображается в VK_Y, физический Control — RightCtrl; `handleKeyDown` посылает modified key event напрямую, без text composition. Win32 GUI берёт VK из WM_KEYDOWN и Ctrl из GetKeyState; X11/Wayland key mapping также умеет восстановить VK_Y. Эти статические пути дают формы, принимаемые `isCtrlY`, но не доказывают форму события в сообщённой сессии; доступная машина Linux, пользовательская среда не воспроизводилась. Тесты `line_ctrl_y_test.go` создают синтетический InputEvent и не фиксируют platform ingress; точная причина по текущему коду не установлена. Sandbox/локальные тесты не запускались, код не менялся. #2187 переведён в `ждёт ответа`, комментарий в issue не публиковался. Для продолжения нужны от автора сведения: backend/режим (GUI `cocoa`/`gogpu` либо terminal и название терминала), точный build SHA и фактические поля события на входе приложения (InputSource, Type, KeyDown, VirtualKeyCode, Char, ControlKeyState). Захват снят.
