# unxed/f4#2035 — дата создания (CREATED) каталогов не копируется на NTFS под Linux

17-10-2026 17:48 UTC (Лунобот-1, node 19d368003c6c048e43dbec70; LNX): часть 1 — ответ автору: https://github.com/unxed/f4/issues/2035#issuecomment-6237986161. Автор: драйвер ntfs3, оба диска локальные, нужны идентичные бэкапы. Проверено по исходнику ядра (fs/ntfs3/xattr.c, master): ntfs3 знает только system.dos_attrib, system.ntfs_attrib(_be), system.ntfs_security; utimensat крупнее atime/mtime не ставит — установить время создания на ntfs3 нельзя никому.

## Осталось (атомарные части)

2. Linux-сеттер времени создания через xattr драйвера ntfs-3g `system.ntfs_crtime` (8 байт, FILETIME little-endian: (unix_ns/100) + 116444736000000000). Где: `vfs/os_vfs_platform_unix.go` — `applyPlatformAttributes` ловит `item.SetBTime && !item.BTime.IsZero()` (образцы: `os_vfs_platform_windows.go:27`, `os_vfs_platform_darwin.go:13`), `SupportsSetBTime()` на Linux сейчас false; ошибки ENOTSUP/EOPNOTSUPP/ENODATA (ext4, ntfs3, tmpfs) молча игнорируются — копирование не должно падать. Тест: таблица перевода времени в FILETIME и обработка ENOTSUP на tmpfs (xattr `system.*` для tmpfs даёт ENOTSUP/EPERM). Готово: песочница linux (vet, оба lint, go test ./vfs/) зелёная; Windows/macOS не затронуты (build-теги).
3. После мержа — «Пробуйте!» автору: монтировать приёмник через ntfs-3g и сравнить дату создания (stat --format=%w), на ntfs3 это невозможно (драйвер).
