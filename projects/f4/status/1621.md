# f4 #1621 — поведение CtrlF1 и CtrlF2 при показанном терминале

Суть: после Esc (панели скрыты, показан терминал) первое нажатие CtrlF1/CtrlF2
не показывало панели (нужно было нажать дважды), а повторные нажатия одного
CtrlF1 без CtrlF2 вообще никогда не показывали левую панель. Причина: Esc
(`TogglePanelsVisibility`) скрывает панели, трогая только `ShowPanels`, не
трогая `ShowLeftPanel`/`ShowRightPanel` — а обработчики CtrlF1/CtrlF2 судили
«всё скрыто» по устаревшим `ShowLeftPanel`/`ShowRightPanel`, а не по
фактическому `ShowPanels`.

Статус: фикс уже был закоммичен в `lunobot/staging` (коммит `80726a42`,
"panel: fix Ctrl+F1/Ctrl+F2 needing extra presses after Esc hides panels",
трейлер `Touch: #1621`, есть regression-тест
`TestPanelsFrame_CtrlF1RestoresAfterEscHide_Issue1621`) до захвата этой сессией
— видимо, предыдущим кругом того же узла. Проверил логику фикса вручную
(прошёл оба сценария из тикета шаг за шагом) — оба симптома устраняются.
Коммит ещё не в `main` (`git merge-base --is-ancestor 80726a42 origin/main` →
NO) — ждёт поезда `train.py tick`. Новых кодовых правок в этом шаге не
делалось, коммитить нечего.

Дальше: когда поезд довезёт этот коммит до `main`, тикету нужно отправить
«Пробуйте!» с текстом из секции `Проверить:` коммита 80726a42 (это сделает
`tick`, увидевший зелёный поезд, по § 7.3/§ 7.2 п. 4).
