Часть 14 (28-09-2026, Лунобот-3, `4b6178b3` в `lunobot/staging`) — выбор
отдельных строк внутри фрагмента, в обе стороны (F4 и Shift+F4). Выбран
вариант (б) — строковый выбор; он покрывает и (а) «разбить фрагмент» (`s` в
`git add -p`): отметить строки одного участка. `diffHunk.selected` →
`picked []bool` по строкам. Insert/пробел на строке `+`/`-` — только эта
строка, курсор на строку ниже; на `@@`/контексте — весь фрагмент (частично
отмеченный добирается целиком), курсор на следующий `@@`; у частичного
фрагмента в заголовке `[k/n]`. `buildPatch` → `(string, error)`:
`pickedBody` — сторона индекса (`-` при добавлении, `+` при снятии с `-R`)
сохраняет все строки, невыбранные изменённые становятся контекстом; другая
сторона теряет невыбранные вместе с маркером `\ No newline`; счётчики
пересчитываются, начало не-индексной стороны сдвигается на дельту уже
перестроенных hunks (`linesBefore`/`startAfter`, учтены стороны с count 0).
Отказ с тостом, без apply: часть фрагмента нового/удалённого файла
(`errWholeFileOnly`, `/dev/null` в заголовке) и выбор, при котором строка без
перевода строки оказалась бы в середине (`errNoNewlineInside`). Тесты на
реальных репозиториях с `git show :f.txt`: stage «+A» и «+X» (не «-25») —
сдвиг второго hunk на 1, а не 2; unstage «+B» и «-25» полностью
проиндексированного — сдвиг «-» назад на 1; оба дают одно содержимое
индекса; плюс файл без финального перевода строки, переключения строка/кусок,
юнит-тесты обеих сторон и отказов, дамп. Песочница: run 36441674157 —
зелёная. Комментарий в тикете: issuecomment-5872899770.

## Дальше (по одной части за круг)

- Кандидат: частичный выбор для нового/удалённого файла — сейчас `Insert`
  берёт такой файл только целиком (`buildPatch` отказывает с
  `errWholeFileOnly`, потому что часть новой/удалённой хунка нельзя
  представить без превращения создания/удаления в обычную модификацию, а
  для F4/Shift+F4 такого файла Insert остаётся единственным способом
  добавить/убрать его). Оценка сложности: нужен способ добавить в индекс
  только часть содержимого нового файла построчно — `git diff` его тоже не
  показывает (как и для `??`), поэтому потребуется отдельный путь
  построения патча "с нуля" (`--- /dev/null` → выбранные строки), а не
  переиспользование существующего `parseFilePatch`/`buildPatch` над
  реальным git-диффом; вероятно жизнеспособнее части 16 по объёму работы,
  но требует нового способа получить построчное содержимое файла и его
  кодирования в валидный unified diff вручную — оставлено на следующий
  круг.
- Маркер `\ No newline` как отдельная строка списка: Insert на нём
  переключает весь фрагмент (как контекст) — при жалобах сделать
  некликабельным.
