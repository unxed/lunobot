# f4#1623 — проверка контрольных сумм (аналог IntChecker)

Спецификация автора (tarlabnor, комментарий 2026-09-28): команда → меню
«Generate hashes» / «Validate files»; в Generate — алгоритм (радиокнопки),
вывод (Single file / Separate hash files / Directory hash files / Display),
опции (рекурсия, абсолютные пути, фильтр по маске), кодировка файла;
Validate — по файлу сумм под курсором или с запросом пути, запрос каталога
при ненайденных файлах. Прогресс (текущий + общий) и отмена обязательны.
Образец — https://github.com/lazyhamster/IntChecker

   диалог возвращается с просьбой указать каталог; прогресс и отмена как в

   `<имя каталога><ext>` / окно с «Копировать в буфер» и «Сохранить в

5. ГОТОВО (Лунобот-3, 28-09-2026, `a8f0b325` в `lunobot/staging`):
   «Кодировка файла» при генерации — UTF-8 / UTF-8 с BOM / ANSI / OEM (как в
   IntChecker; системная, совпадающая с UTF-8, не дублируется), для всех
   выводов и «Сохранить в файл»; имена, не представимые в кодировке
   (круговая проверка EncodeBytes/DecodeBytes), пропускаются и перечисляются
   в итоге. При проверке — комбобокс «Автоопределение» / UTF-8 / ANSI / OEM;
   курсорный путь — автоопределение: BOM (UTF-8/UTF-16) → валидный UTF-8 →
   vfs.DetectEncoding с запасной ANSI; UTF-8 без перекодировки (сырые имена).
   Тест «сгенерировал в X → проверил» для UTF-8, UTF-8+BOM, 1251, 866,
   KOI8-R с кириллицей. Песочница зелёная (run 36439109919, вкл. cmd/f4).
   Комментарий: https://github.com/unxed/f4/issues/1623#issuecomment-5872503211

## Пункт 3 отзыва — прогресс: время/ETA/скорость (28-09-2026, Лунобот-3)

ГОТОВО (`2528ce1c` в `lunobot/staging`, ещё не в main): диалог прогресса «Вычислить
хэши...»/«Проверить файлы...» уже переиспользует `fileops.FileOpProgressDialog` (тот же, что
и у копирования/удаления) через `app.RunAdvancedProgressTask` — там уже была метка скорости,
просто `speedText` всегда передавался пустым. Добавлен `plugins/intchecker/progress.go`
(`progressSpeed`) — тот же формат строки, что у copy/move (`internal/fileops`,
`getGlobalStats`): «Time: hh:mm:ss  Remaining: hh:mm:ss  <скорость>/s», локализован через
новые ключи `IntChecker.ProgressElapsed`/`ProgressRemaining`/`ProgressRemainingUnknown`/
`ProgressRemainingLong` (en+ru). Подключено к обеим точкам, где реально читаются байты:
`hashInputs` (генерация) и фаза verifying в `runValidate` (проверка); фаза locating (только
`Stat`, без чтения) не тронута. Тесты: `plugins/intchecker/progress_test.go` (расчёт elapsed/
ETA/скорости на фиксированных офсетах времени) + регрессия в `generate_test.go`/
`validate_test.go` (последний `UpdateTransfer` несёт непустой speed/time text). `gofmt -l`
чисто; сборка/тесты — по песочнице CI поезда, не локально.
