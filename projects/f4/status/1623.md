# f4#1623 — проверка контрольных сумм (аналог IntChecker)

Спецификация автора (tarlabnor, комментарий 2026-09-28): команда → меню
«Generate hashes» / «Validate files»; в Generate — алгоритм (радиокнопки),
вывод (Single file / Separate hash files / Directory hash files / Display),
опции (рекурсия, абсолютные пути, фильтр по маске), кодировка файла;
Validate — по файлу сумм под курсором или с запросом пути, запрос каталога
при ненайденных файлах. Прогресс (текущий + общий) и отмена обязательны.
Образец — https://github.com/lazyhamster/IntChecker

   Тест «сгенерировал в X → проверил» для UTF-8, UTF-8+BOM, 1251, 866,
   KOI8-R с кириллицей. Песочница зелёная (run 36439109919, вкл. cmd/f4).

## Пункт 5 отзыва — снятие выделения после успеха (28-09-2026, Лунобот-3)

ГОТОВО (`9fe817e8` в `lunobot/staging`, ещё не в main): у `vfs.App` не было вообще никакого
способа снять программное выделение (marked/Insert) с панели — сам примитив уже существовал,
но только внутри `internal/panel` (`PanelSelectionToken`/`CaptureSelectionToken`/
`ClearSelectionIfUnchanged`, уже используется встроенной командой «Apply command»,
`internal/panel/apply.go`), а положить его тип прямо в интерфейс `vfs.App` нельзя — цикл
импорта (`internal/panel` уже импортирует `vfs`). Добавлен новый опциональный capability
по образцу уже существующего `vfs.SelectedIsDirHost` (f4#1356): `vfs.SelectionClearHost` с
`CaptureSelectionToken(name) (vfs.SelectionToken, bool)`, где `vfs.SelectionToken` — непрозрачный
хендл с методом `Clear() bool`. `PanelsFrame` (`internal/panel/frame.go`) реализует его через
тот же `FileSystemPanel.CaptureSelectionToken`/`ClearSelectionIfUnchanged`; любая другая
реализация `vfs.App` (включая все тестовые заглушки по плагинам) интерфейс не реализует —
токен просто не берётся, без последствий для остального дерева.

`plugins/intchecker`: `startGenerate` берёт токен на каждое отмеченное имя (`job.names`) перед
запуском, `finishGenerate` снимает выделение только на успешном пути (не на отмене, не на
«нечего хэшировать», не на ошибке чтения/записи). `startValidate`/`finishValidate` — токен на
сам файл сумм, только если он лежит прямо в текущем каталоге панели; снимается по завершении
проверки (не на отмене, не на ошибке, не когда диалог переоткрывается с просьбой указать
другой каталог). `gofmt -l` чисто. Диагностика: `go vet`
(`./vfs/... ./internal/panel/... ./plugins/intchecker/...`), `go test ./plugins/intchecker/...`,
`go test ./cmd/f4/` (обязательные аудит-тесты) и оба прогона golangci-lint — один непроверенный
проход в песочнице, без поллинга:
https://github.com/unxed/f4/actions/runs/36471854034

Осталось из пяти пунктов отзыва: 1 (сохранение параметров) — по свежей `DISPATCH.md` в работе

## Инцидент: красный staging из-за нехватки перевода (28-09-2026, Лунобот-3)

`train.py tick` нашёл красный `lunobot/staging`: `TestRussianTranslationIsComplete`
(`internal/i18n/lang_ru_complete_test.go`) упал — `ru.lng` не хватало 4 ключей из `en.lng`:
`IntChecker.Command.Generate`, `IntChecker.Command.Generate.Desc`, `IntChecker.Command.Validate`,
`IntChecker.Command.Validate.Desc`. Причина — `31a9dba75` (пункт 4 отзыва, меню Files) добавил
эти ключи только в `en.lng`, забыв `ru.lng`. Бисект откатил из staging оба коммита пункта 4 и
5 отзыва (`31a9dba75` и зависимый от него `9fe817e80`, деселект после успеха).

Починка: оба коммита пересозданы (`git cherry-pick`) поверх актуального `lunobot/staging` —
конфликтов не было, ветка ушла вперёд только на несвязанный `fileops` коммит. Добавлен третий,
отдельный коммит с четырьмя недостающими строками перевода в `ru.lng` (терминология — по
образцу уже существующих `IntChecker.*`/`Archive.Command.*` строк в этом же файле). Итог
приземлён `train.py land`:

- `0df1d287...` — `intchecker: deselect files and folders after a successful hash/verify run`
  (было `9fe817e80`)

- `c2fb9fc5...` — `i18n: add missing ru.lng translations for IntChecker Files-menu commands`
