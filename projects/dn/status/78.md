# dn#78 — Access violation в TWhileView.Write при копировании каталога на linux-aarch64

15-10-2026 08:0x UTC (Лунобот-1, node 19d368003c6c048e43dbec70; LNX, круг): чтение кода. Сборка CI для aarch64 — `-gl` БЕЗ оптимизации (`DN_OPT_aarch64` в `dn/build.env`), поэтому версия «ошибка кодогенерации -O2» из записи в `status/40.md` не подтверждается. Строка 268 `progress.pas` — `if N < Lines.Count`, т.е. нарушение доступа на `Self`/`Lines` — подозрение: `Info` (переменная `FilesCopy`) уже освобождён (`Info.Free`, `filecopy.pas` ~2492/2525 после отмены/Stop) или не тот объект, а вложенные `MakeDirectories`/`CopyI` продолжают писать в него; на x86_64 освобождённая память остаётся читаемой. НЕ проверено запуском.

Диагностика (не для мержа): ветка `tmp/19d3/dn78-diag` (клон `/tmp/lunobot-1/work/dn76e-1015-0730/dn`, коммит см. `git log`): `dn-linux.yml` урезан до одного job `diag` (aarch64 обычная сборка / aarch64 с `-gh` (heaptrc) / x86_64 с `-gh`), `dn-linux-ops.py` без SKIP на aarch64. Прогон запускается пушем ветки (trigger push на tmp/** с изменённым workflow).

Осталось: (1) по логу прогона `diag`: на aarch64 default — полный стек с номерами строк и значение `Info`; `-gh` на x86_64 должен воспроизвести падение (heaptrc заполняет освобождённое `$F0`) — тогда виновен use-after-free; (2) исправить: после `Info.Free` ни одна вложенная процедура не пишет в `Info` (флаг/`Info := nil` и проверка в `TWhileView.Write` не годятся — нужна причина: почему вызов идёт после отмены) — отдельная ветка `lunobot/pr/78-<ключ>` от main, убрать SKIP из `tools/dn-linux-ops.py` в том же PR; (3) удалить ветку `tmp/19d3/dn78-diag` после разбора.
