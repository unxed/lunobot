# dn#78 — Access violation в TWhileView.Write при копировании каталога на linux-aarch64

15-10-2026 (Лунобот-1, node 19d368003c6c048e43dbec70; LNX): часть 1 из 1 сделана, PR https://github.com/unxed/dn/pull/79 (ветка `lunobot/pr/78-1of1`, один коммит `fa5c7e1`, клон `/tmp/lunobot-1/work/dn78pr-1015-0832/dn`). Локально не собиралось (dn — `Отладка GitHub CI: да`), коммит проверяет только CI PR.

Причина, доказанная прогонами диагностической ветки `tmp/19d3/dn78-diag` (не для мержа; прогоны https://github.com/unxed/dn/actions/runs/38705834943, https://github.com/unxed/dn/actions/runs/38706281025, https://github.com/unxed/dn/actions/runs/38706714516): FPC 3.2.2 на linux-aarch64 отдаёт процедуре, вложенной на ДВА уровня (`FilesCopy` → `MakeDirectories` → `CopyI`/`CopyF`), чужие значения переменных «деда» по статической ссылке. Это не оптимизация (тот же стек при `-gl` и `-gh`) и не use-after-free (на x86_64 с heaptrc падения нет). Проверка `Pointer(Info) <> Pointer(глобальная копия)` в `CopyI` на aarch64 истинна. С `Info` через переменную модуля падение исчезло, но копирование не стартовало (F5, `destination`, Enter — окна прогресса нет, 0 из 4096 файлов): остальные переменные «деда» (`CopyCancel` и т. д.) читаются так же неверно.

Что в PR: все вложенные процедуры `MakeDirectories` (CopyI, CopyF, CopyLinkOf, NoCheck, IsNetworkPath) вынесены на уровень `FilesCopy`; `S`, `FrPos`, `KillDescrOf` стали переменными `FilesCopy`; SKIP `background_copy` на aarch64 убран из `tools/dn-linux-ops.py`. Код процедур не менялся (только перенос и отступ).

Осталось: (1) по итогам CI PR (строка `CI.md`): `dn-linux` на aarch64 должен пройти `background_copy`; ошибка КОМПИЛЯЦИИ (имя не найдено, порядок объявлений) — поправить в ветке PR; если копирование на aarch64 всё ещё не стартует — смотреть в `tools/dn-linux-ops.py`, что на экране после F5/Enter (диагностическая ветка печатает экраны `dn78 after F5/typing/Enter`); (2) влить PR (§ 7.3), в тикет — «Пробуйте!»: на Linux aarch64 копирование каталога по F5 не падает; (3) другие процедуры, вложенные на два и более уровней в `dn/src/*.pas`, на aarch64 читают неверные переменные «деда» так же — найти их (`grep` по отступу вложенных `procedure`/`function` внутри вложенных) и вынести отдельным тикетом/частью; (4) удалить ветку `tmp/19d3/dn78-diag` и запись в `BRANCHES.md`, каталоги `/tmp/lunobot-1/work/dn76e-1015-0730`, `/tmp/lunobot-1/work/dn78-1015-0825` после слияния PR.
