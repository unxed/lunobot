# Unit TvCodePg and its table file tvcp.inc - functional specification (specs name: tvcodepages)

## 1. Purpose

TvCodePg keeps the one single-byte OEM code page that the screen of a program shows, and translates between a byte of that page and a Unicode code point. Text in the library is UTF-8, but a byte that is not part of valid UTF-8 is "a character of the code page"; the DOS back end writes screen cells as bytes of the page; control characters 0..31 and 7Fh are displayed as the IBM PC graphic symbols. This unit gives the byte -> Unicode map, the reverse map, the UTF-8 form of a byte, and a table of plain ASCII substitutes for characters that a page lacks.

Seventeen pages are built in: 437, 737, 775, 850, 852, 855, 857, 858, 860, 861, 862, 863, 864, 865, 866, 869, 1125. The tables live in the include file `tvcp.inc` (generated by a tool from the Python codecs; the low half is replaced by the IBM PC glyphs). The unit keeps global state (the current page and its reverse map); it is not thread-safe: CpSelect must not run concurrently with any other routine. The default page after start-up is 866 (the library's rule; the Turbo Vision original defaults to 437).

Related units (specified elsewhere, they use this one): TvGlyphs (glyph names to code points and to page bytes), TvDosNames (file names between a page-based program and a UTF-8 DOS; see tvglyphs.md and tvdosnames.md), and TvCharset (a separate, bigger set of conversion tables, with no "current" page; see tvcharset.md). The case-mapping routines `CpUpper` / `CpLower` of TvUStr work on Unicode code points and have nothing to do with code pages despite the name.

## 2. Interface

```pascal
unit TvCodePg;

interface

const
  cpIdCp437 = 437;
  cpIdCp866 = 866;
  cpIdCp1125 = 1125;

function CpSelect(Id: Integer): Boolean;
function CpCurrent: Integer;
function CpToUnicode(B: Byte): LongWord;
function CpFromUnicode(CodePoint: LongWord): Byte;
function CpToUtf8(B: Byte; Buf: PByte): Integer;
function CpFallback(CodePoint: LongWord): Byte;
```

The tables (private to the unit, in tvcp.inc): 17 constants of type `array[0..255] of Word`, named Cp437, Cp737, Cp775, Cp850, Cp852, Cp855, Cp857, Cp858, Cp860, Cp861, Cp862, Cp863, Cp864, Cp865, Cp866, Cp869, Cp1125.

## 3. Behaviour

### 3.1 CpSelect(Id), CpCurrent

CpSelect makes the page with the given Windows/DOS number current and rebuilds the reverse map; returns True. If Id is not one of the 17 numbers (for example 0, 1, 720, 1251) it returns False and leaves the current page unchanged. Selecting the current page again is allowed. CpCurrent returns the number of the current page (866 at start-up; after a refused selection, the number of the page that was current).

### 3.2 CpToUnicode(B)

The Unicode value that the current page gives to byte B: the table entry for B. Defined for all 256 values of B. The value $FFFD (the replacement character) is returned for the bytes that the page leaves undefined (section 4.3). Control bytes return the IBM PC symbol of that position (section 4.2), except byte 0, which returns U+0000. The result always fits 16 bits.

### 3.3 CpFromUnicode(CodePoint)

The byte of the current page whose table value is CodePoint; 0 if there is none. CodePoint above $FFFF never matches. Lookup is by binary search in a reverse table made of all 256 pairs (value, byte) sorted by value, ties (several bytes with the same value) ordered by byte. The byte returned when two bytes share a value is the lowest one: in pages 775, 850, 857, 858, 863 U+00B6 returns 14h and U+00A7 returns 15h (not F4h/F5h, nor 86h/8Fh in 863 or FDh in 855). Examples: cp866 U+0410 -> 80h, U+0430 -> A0h, U+0401 -> F0h, U+2500 -> C4h, U+263A -> 01h, U+2302 -> 7Fh, U+0041 -> 41h; cp437 U+00C7 -> 80h, U+03B1 -> E0h; cp857 U+011F -> A7h (test); cp866 U+4E2D (a CJK character) -> 0.
Zero is also the result for "not found", so U+0000 and an unmappable character cannot be told apart; callers treat 0 as "no byte" (U+0000 itself is never shown through this function).
The replacement character: a table that has undefined bytes stores $FFFD for them (4.3), so a plain implementation would return the lowest undefined byte for U+FFFD (for example 80h in cp869). That is accidental; the intended result is 0 for U+FFFD in every page (an undefined byte is not a character that can be written). Tests never ask for it.

### 3.4 CpToUtf8(B, Buf)

Writes the UTF-8 encoding of CpToUnicode(B) to Buf (the buffer must hold at least 4 bytes) and returns the number of bytes written: 1 for values below $80 (including byte 0 -> one zero byte, and bytes 20h..7Eh), 2 for $80..$7FF, 3 above (all table values are in the BMP, so 4 is never returned). It does not write a terminator. Examples: cp866 byte 80h -> D0 90 (2 bytes); cp437 byte 80h -> C3 87; byte 01h (any page) -> E2 98 BA; byte 7Fh -> E2 8C 82 (U+2302); an undefined byte -> EF BF BD.

### 3.5 CpFallback(CodePoint)

Independent of the current page. The plain ASCII byte that stands for a character a page may lack, or 0 if there is none (callers then show `?`). Rules, first match wins:
* `-`: U+2500, 2501, 2504, 2505, 2508, 2509, 254C, 254D, 2574, 2576, 257C, 257E (light and heavy horizontals and half lines); U+2580..U+2587 (upper and lower blocks); U+2013, U+2014 (dashes).
* `=`: U+2550.
* `|`: U+2502, 2503, 2506, 2507, 250A, 250B, 254E, 254F, 2551, 2575, 2577, 257D, 257F (verticals); U+2589..U+2590 (left blocks, left half, right half).
* `#`: U+2588 (full block). `.`: U+2591 (light shade). `:`: U+2592. `%`: U+2593.
* `<`: U+2190, U+25C4. `>`: U+2192, U+25BA. `^`: U+2191, U+25B2. `v`: U+2193, U+25BC.
* `*`: U+2022 (bullet), U+2219, U+25CF.
* apostrophe (27h): U+2018, U+2019. double quote (22h): U+201C, U+201D. space: U+00A0.
* `+`: any other code point in U+2500..U+257F (corners, tees, crosses, double and mixed lines).
* anything else: 0.
Tests: U+2500 -> `-`; U+2551 -> `|`; U+2554 -> `+`; U+2588 -> `#`; U+2190 -> `<`; U+4E2D -> 0.

### 3.6 Users' view (informative)

* TvDos writes a glyph to the DOS screen as `CpFromUnicode(cp)`, else `CpFallback(cp)`, else `?`. It selects the page that the DOS host reports and falls back to 437 if CpSelect refuses it.
* TvText / TvCell / TvMem turn a byte that is not valid UTF-8 into `CpToUtf8` of the byte, and TvText/TvInput/TvClip/TvUtil map typed or pasted Unicode characters to bytes with `CpFromUnicode` (0 = not representable).
* TvGlyphs.GlyphByte: takes `CpFromUnicode(cp)` when it is non-zero, the glyph is above U+007F and the byte is below 20h or at least 7Fh; otherwise the IBM PC byte of its own table (so frames always have their PC position even on a page that lacks them, and are the same bytes on every page but cp864).
* TvDosNames uses `CpToUnicode` to turn page bytes of a file name to UTF-8 and `CpFromUnicode` to go back; a zero result means "the page lacks it".

## 4. The tables

### 4.1 Indexing

Each table is indexed by the byte value 0..255; the entry is the 16-bit Unicode value shown for that byte, or $FFFD for an undefined byte. The same layout is used in every page: entries 20h..7Eh are the identity (ASCII) in all 17 pages, including cp864 (where IBM's own table differs at 25h, the table here keeps ASCII; intended).

### 4.2 The low half

For all 17 pages the entries 00h..1Fh and 7Fh are the same: byte 00h -> U+0000; and 01h..1Fh and 7Fh -> the IBM PC character symbols of code page 437 (the glyphs a DOS screen shows for control codes), namely 01h U+263A, 02h U+263B, 03h U+2665, 04h U+2666, 05h U+2663, 06h U+2660, 07h U+2022, 08h U+25D8, 09h U+25CB, 0Ah U+25D9, 0Bh U+2642, 0Ch U+2640, 0Dh U+266A, 0Eh U+266B, 0Fh U+263C, 10h U+25BA, 11h U+25C4, 12h U+2195, 13h U+203C, 14h U+00B6, 15h U+00A7, 16h U+25AC, 17h U+21A8, 18h U+2191, 19h U+2193, 1Ah U+2192, 1Bh U+2190, 1Ch U+221F, 1Dh U+2194, 1Eh U+25B2, 1Fh U+25BC, 7Fh U+2302. (Standard: the Unicode Consortium's notes on the IBM PC graphic set, "CP437 with graphics", i.e. the mapping the Python codec `cp437` documents for the display glyphs.)

### 4.3 The high half (80h..FFh)

Each page's high half follows the Unicode Consortium mapping file for the IBM/Microsoft OEM code page of that number (the VENDORS/MICSFT/PC directory files CP437, CP737, CP775, CP850, CP852, CP855, CP857, CP860, CP861, CP862, CP863, CP864, CP865, CP866, CP869), taken through the Python standard codec of the same name. Page 858 is CP850 with D5h = U+20AC (euro) instead of U+0131 (the one difference, per Microsoft's definition of 858). Page 1125 (also called 866u, the Ukrainian variant) is CP866 with F2h..F9h = U+0490, U+0491, U+0404, U+0454, U+0406, U+0456, U+0407, U+0457 (Python codec `cp1125`). Undefined bytes (value $FFFD): cp857 D5h, E7h, F2h; cp864 9Bh, 9Ch, 9Fh, A6h, A7h, FFh; cp869 80h-85h, 87h, 93h, 94h. All other pages define all 256 bytes.

Pages 775, 850, 852, 855, 857, 858 and 869 have the same characters at B0h-B4h, B9h-BCh, BFh-C5h, C8h-CEh, D9h-DCh, DFh but letters instead of the mixed single/double line characters at B5h-B8h, BDh, BEh, C6h, C7h, CFh-D8h, DDh, DEh. Page 864 has no frame block at B0h..DFh (its frames and shades sit in the 80h-8Fh area, for example 80h is U+00B0). This is why a glyph needs CpFromUnicode, then CpFallback. Additional test facts: byte 7Fh -> U+2302; byte 00h -> U+0000; byte FFh -> U+00A0 except cp864 (undefined, U+FFFD).

### 4.4 Reverse map

Built when a page is selected (and once at unit start for 866): 256 pairs (value, byte) sorted by value, equal values ordered by byte. Undefined bytes participate with value $FFFD (see 3.3). Pages with equal values for different bytes: 775, 850, 857, 858 (U+00B6 at 14h and F4h; U+00A7 at 15h and F5h), 852 (U+00A7 at 15h, F5h), 855 (U+00A7 at 15h, FDh), 863 (U+00B6 at 14h, 86h; U+00A7 at 15h, 8Fh), 869 (U+00A7 at 15h, F5h). Lowest byte wins.

## 5. Dependencies

* TvUtf8 (implementation only): the UTF-8 encoder (`Utf8Encode(CodePoint, Buf): Integer`, returning 1..4 bytes).
* No others. The tables are an include file (`{$I tvcp.inc}`) whose constants have names as in section 2.

## 6. What the tests pin down

* tests/t_text.pas: default page 866 (`CpCurrent = 866`); byte 80h is Cyrillic A (UTF-8 D0 90) in 866 and C-cedilla (C3 87) in 437; CpSelect(437) succeeds and CpCurrent = 437; CpSelect(1) is False and the current page stays 437; 850 byte 9Bh = U+00F8; 852 byte A4h = U+0104; 855 byte 80h = U+0452; 737 byte 80h = U+0391; 862 byte 80h = U+05D0; 857 CpFromUnicode(U+011F) = A7h; 869, 775, 858, 860, 861, 863, 864, 865 are selectable; control bytes 01h and 7Fh display as U+263A and U+2302 (E2 98 BA, E2 8C 82).
* tests/t_cpall.pas, for each of the 17 pages: it can be selected; every byte 20h..FFh except 7Fh whose value is not U+FFFD maps back to a non-zero byte through CpFromUnicode; the 11 glyphs U+2500, 2502, 250C, 2510, 2514, 2518, 2550, 2551, 2554, 2557, 2588 each have either a page byte or a CpFallback sign, and when the page has them GlyphByte equals CpFromUnicode; U+2591..U+2593, U+2219 and U+25B2 each have a byte or a fallback.
* tests/t_cell.pas: CpFallback examples of 3.5. tests/t_ascii.pas: CpToUtf8 of high bytes. tests/t_dosnam.pas: Cyrillic file names through 866.
Recommended extra tests: round trip byte -> value -> byte for all defined bytes 20h..FFh (except those listed in 4.4 where the lowest byte comes back) in every page; CpToUtf8 length equals the UTF-8 length of CpToUnicode; CpSelect(866) restores defaults.

## 7. Observed oddities

* CpFromUnicode returns 0 for "not found", conflicting with U+0000. Intended (callers use 0 as "no byte").
* The reverse map includes undefined bytes under $FFFD, so U+FFFD maps to a nonzero byte in pages 857, 864, 869. Accidental; intended result is 0 (3.3).
* Equal values on several bytes: the lowest byte wins, so the control position 14h/15h is returned for the pilcrow and section sign, not the high-half byte. Intended as deterministic; the round-trip test of t_cpall only requires non-zero.
* CpToUtf8 requires a 4-byte buffer though only 3 bytes are ever used. Intended (safe contract).
* Page 1125 and the 864 page: 864 does not keep IBM's percent sign position; documented in 4.1. Intended.
* The header comment of the old unit says the DOS "default is 437 in the original"; here the default is 866. Intended.
* The page number list in the header comment is missing 720 and the Windows pages; they are in TvCharset only. Intended: TvCodePg is the DOS OEM set only.
