# tv3

- Код: https://github.com/unxed/tv3 (Free Pascal, классовый перевод Turbo Vision magiblot/tvision `b4831e2`)
- Задачи: тикеты и PR этого же репозитория; план стабильного среза — unxed/tv3#1
- PR: туда же, ветка `lunobot/pr/<ключ>` -> PR -> мерж в `main`
- Зависимости: `unxed/dn` подключает tv3 как подмодуль `tv/`; `unxed/tv` (исторический архив) удалён владельцем 21-10-2026, его старая история есть только в копии у владельца. Из задачи tv3 их не менять.
- Язык общения: по языку автора тикета (README и тикеты репозитория — английский)
- Режим публикации: PR
- Отладка GitHub CI: да
- Диагностические workflow: нет; единственный `ci.yml` (Linux x86_64: `linux`, `pty`, `generated`) идёт на push и PR и гоняет всё, что нужно для проверки (workflow_dispatch тоже включён)
- Обязательная проверка: `ci` целиком (три job'а) на точном SHA
- Покрытие: единицы измерения нет (Free Pascal); цель не задана, процент не выдумывать
- Особенности: проверена только Linux x86_64; Windows, DOS, i386, aarch64, macOS в CI нет. Стабильным называть только SHA с зелёным `ci`.
- Вливание: `CLAUDE.md` репозитория (правило 4) требует `AUDIT PASS` от `tools/audit/run.sh`, а baseline `main` даёт `AUDIT FAIL` (32 совпадения, unxed/tv3#3). Решение владельца 21-10-2026 (unxed/lunobot#234, вариант 1): пока идёт разбор baseline, PR tv3 вливать можно, если его голова не добавляет новых совпадений к baseline `main` — проверка в CI песочницы: `gh workflow run tv3-audit.yml --repo unxed/sandbox --ref main -f repo=unxed/tv3 -f refs="main <sha головы PR>"`, в артефакте `new.txt` (ключи совпадений головы, которых нет у `main`) должен быть пуст; результат — комментарием в PR до вливания; артефакт (в нём выдержки корпусов) удалить после скачивания (`gh api -X DELETE repos/unxed/sandbox/actions/artifacts/<id>`). Корпуса только в CI, локально `run.sh` не запускать. Разбор baseline опубликован: https://github.com/unxed/tv3/issues/3#issuecomment-6320902977 (35 совпадений = 6 мест, все ложные). Переписывание истории/force-push — только отдельным решением владельца; вопрос с вариантами и рекомендацией — https://github.com/unxed/tv3/issues/3#issuecomment-6320910742 (до ответа действует правило «без новых совпадений»). Обязательная проверка `ci` — как прежде. Обновление 21-10-2026: по ответу владельца (вариант 1 вопроса https://github.com/unxed/tv3/issues/3#issuecomment-6320910742) 6 разобранных мест внесены в `tools/audit/known.txt` поточечно (окно, корпус файл:строка, причина; unxed/tv3#13, `132ffb4`): `run.sh` на `main` даёт `AUDIT PASS` (прогон https://github.com/unxed/sandbox/actions/runs/39638302028). Дальше правило 4 `CLAUDE.md` действует как написано: PR вливать только при `AUDIT PASS` на голове (тот же `tv3-audit.yml`, `refs="main <sha головы>"`); новую запись в `known.txt` — только после разбора совпадения в тикете, с технической причиной.
- Включение в `projects/INDEX.md`: пока не согласовано владельцем (порядок приоритета).
- NOTICE, строка `commit:` (постоянное решение владельца 21-10-2026, unxed/lunobot#233): на вопрос «разрешаете ли боту впредь самому обновлять строку `commit:` в NOTICE при побайтном обновлении вендоренного файла» владелец ответил «да». Условие: вендоренный файл в PR побайтно равен файлу источника на указанном коммите (git sha blob'ов совпадают: `gh api repos/<источник>/contents/<путь>?ref=<коммит> --jq .sha` против того же для файла в PR) и в NOTICE меняется только строка `commit:`. Текст лицензии, копирайты, `LICENSE` и прочие правовые тексты (правило 5 `CLAUDE.md` репозитория) — по-прежнему только решением владельца.
